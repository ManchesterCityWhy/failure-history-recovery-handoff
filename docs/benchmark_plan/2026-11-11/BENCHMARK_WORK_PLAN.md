# 失败历史如何指导连续机器人恢复：Benchmark 与数据工厂工作计划

日期：2026-11-11。状态：研究与开发提案；本文件中的新任务、数量和时间均为计划，不是已完成结果。

## 1. 判断与研究定位

这个方向可以做，也可以把 dataset/benchmark 作为论文第一项贡献。但当前 64 条二选一抽屉历史只构成可行性原型，直接更换物体、增加随机种子并扩到几千条，学术增量仍不足。

建议研究问题收敛为：

> 在当前观测不充分的机器人失败状态下，过去的动作—结果证据何时能改变恢复决策，并减少完成原任务所需的再次探索和物理操作成本？

第一项贡献应是：一个覆盖不同失败机制、保留完整失败与恢复动作、可重放且包含强主动重试对照的历史依赖恢复 benchmark。第二项贡献是学习从公开历史抽取有依据的信息，并将其转成冻结动作模型可执行的恢复决策。两者分别验证，benchmark 不以我们的方法获胜作为样本准入条件。

不预先声称首次使用失败经验、首次历史条件化机器人控制、首次恢复数据合成、首次反事实记忆评测或首次连续动作记忆 benchmark。相关工作已经覆盖其中多个部分；潜在贡献在新的失败恢复问题覆盖、数据与执行协议、可检验诊断，以及实证发现。

## 2. 已有实验究竟支持什么

| 已完成实验 | 实际结果 | 对下一阶段的启示 |
|---|---|---|
| 普通恢复 32 例 | 直接继续 21/32；当前帧教师与历史教师均为 22/32 | 一般掉落不一定有历史增量，保留作当前信息充分对照 |
| 搜索连续恢复 64 例 | 128 步：当前帧主动搜索 32/64，历史指导 59/64；480 步：57/64 与 63/64 | 历史可减少重复搜索，收益随预算变化 |
| 同历史的 reset 恢复 64 例 | 128 步：32/64 与 56/64；480 步：56/64 与 64/64 | 在严格相同 RGB 下也存在信息收益 |
| 数据核验 | 64 条唯一失败历史、384 次主恢复执行、63 条连续完整失败→成功轨迹；另有 185 条普通失败 | 采集、快照、动作对齐、分支评测和导出链路可复用 |

当前试验的局限必须进入论文：只有一个二选一搜索家族；第一次错误探测是受控安排；探测后有外部关门；教师包含公开运动学规则；指导条件共享子目标 oracle；只测试一种恢复动作模型和一个随机种子。历史分支还没有自动视频理解模型。233 个成功分支共享 64 条历史，不能当作 233 个独立场景；127 个历史指导成功样本包含连续/reset 两种接入版本。

reset 的 32 对 RGB 逐像素相同，本体数值只有 28 对逐位相同，最大尾差为 5.56e-17。本轮 WAM 不输入本体状态。未来接口要明确本体量化精度，例如 1e-6；原始数值另存用于物理还原，不能用浮点尾差辨识隐藏答案。

现有 64 条及已经查看的旧失败库用于开发、校准与训练准备，不再充当新方法的全新盲测集。

## 3. 相关工作与创新边界

以下为截至本次查阅的论文/作者仓库内容；本轮没有重新运行这些外部系统。

| 工作 | 与我们重合的内容 | 我们需要做出的实质增量 |
|---|---|---|
| [EMem-Bench](https://arxiv.org/html/2609.28236) | Interaction Failure 已测试利用失败反馈揭示的不可见状态避开错误目标；也做历史删除、线索删除与最小 oracle 对照 | 不只做不可用容器选择；增加连续动作、物理场景修复及操作成本，提供源失败到恢复的完整执行记录 |
| [RoboCasa-Mem](https://arxiv.org/html/2611.06475) | 历史依赖的环境/过程记忆，含 DrawerSearch；行为相关的评测约束 | 当前抽屉任务与其主题接近。要研究失败后修复决策与重复探索代价，不能把抽屉搜索本身当创新 |

| [LIBERO-Recovery](https://github.com/liulin815/LIBERO-Recovery) | 可重放失败场景、恢复分层、源 rollout 和专家恢复资源 | 可用作自然失败来源与外部恢复验证；逐条核对历史、锚点与目标是否仍对齐，不能泛称已有工作没有历史 |
| [RecoverBench](https://github.com/ErrorRecoveryBenchmark/ErrorRecoveryBenchmark) | 错误注入、恢复遥操、MimicGen 增广；公开恢复语料已超过一万条 | 自动错误生成和恢复数据扩增已有先例。我们要验证历史是否影响修复选择，不能以合成量取胜 |
| [RACER-DataGen](https://github.com/rich-language-failure-recovery/RACER-DataGen) | 专家轨迹扰动、语言恢复标注、数据增广 | 借鉴分段轨迹与采集流程；其 RLBench/CoppeliaSim 接口不能直接当作当前 MuJoCo 工作流 |
| [Recova](https://arxiv.org/html/2610.01178) | 编码 agent 构建数字孪生、探索并验证恢复程序、持续收集数据 | agent 造场景和验证恢复也不是独立新颖点；我们的数据准入与历史增量评测需有独立研究价值 |

[RoboMME-Plus 作者分析](https://robomme.github.io/blog/)还提示：训练范围内的高分未必说明记忆能力可迁移。因此必须留出未见场景和任务模板，不能只改变同一模板的随机种子。

上述比较支持继续研究，但不足以保证这一组合完全没有先例。P0 仍要逐项审计最接近工作的任务、输入、动作接口和数据字段，形成可核实的差异表。

## 4. 数据单元、失败定义与评测范围

### 4.1 一条唯一失败样本

保存原任务 g、公开历史 H_f、失败判定事件、接入时刻的公开观测 o_f、评测器私有的可还原状态 s_f、源策略及来源标记。每条失败可派生多个恢复分支，但不增加独立源失败数。

H_f 包含同步双相机 RGB、实际执行的动作、本体状态、时间。未执行的预测 action chunk、源策略内部指令、思维过程与私有物体状态不进入默认历史输入。新增力觉只能作为明确声明的传感器赛道，不能把模拟器私有质量、摩擦系数或接触真值冒充传感器。

原任务从第一次尝试前到恢复结束保持一致。不能在失败后临时改成另一个目标，再把完成新目标当恢复成功。

### 4.2 三类失败标记分开保存

- 事件失败：一次可定义的局部操作已结束，但预期效果没有发生，如抬手后物体未随动、搜索一个位置后未找到目标。
- 预算内未完成：首次任务预算结束仍未成功。称 noncompletion，不自动编造具体原因。
- 安全/不可逆失败：单独标注。若任务本身已不可恢复，放入拒绝/求助诊断集，不混入主可恢复任务的 SR 分母。

触发规则、阈值和截断时刻在开发集固定，不依据未来哪次恢复成功来选择“最有价值”的截断点。离线源失败触发可用 evaluator 判定，但所有方法获得相同触发信息；它不等于已解决在线失败检测。

### 4.3 三个评测范围

| 范围 | 环境如何处理 | 主要用途 |
|---|---|---|
| 主赛道：连续恢复 | 从同一失败锚点继续；机器人退回、扶正、重抓等动作全部计费；不提供系统 reset | 真实物理修复与历史信息价值 |
| 诊断赛道：系统 reset 后重试 | 环境只在恢复前恢复指定初态；保留任务相关隐藏条件 θ；明确记录外部帮助 | 隔离状态破坏与信息利用，构造严格观测匹配 |
| 部署附加试验 | 源策略自己执行首次尝试，恢复模块在线接入；初次成功也保留 | 检验自身失败分布、误触发和完整任务收益 |

系统 reset 若重新随机了目标位置、物性或其他 θ，就可能使历史失效。此类全重采样只能作失效记忆对照，不能默认期待历史提高成功率。不同 reset 范围分别报告，不设随意折扣后混合排名。

## 5. 四类候选任务与信息难度

以下为待开发任务家族，尚未验证。每一类先做少量可执行实例，再决定扩量。

| 家族 | 第一次失败留下的证据 | 当前为何不充分 | 恢复必须改变什么 | 优先级/风险 |
|---|---|---|---|---|
| F1 失败搜索与不可行候选排除 | 哪个位置已有效检查、哪次接触未产生目标效果 | 目标/障碍被遮挡，检查状态不再显现 | 检查顺序、接近路径或局部目标 | 易实现；只作基础组，避免占据大多数 |
| F2 掉落去向与目标身份绑定 | 物体滑落/滚入遮挡区域的路径，或目标在旋转/混杂前的身份 | 当前不可见或外观相近 | 去哪里找、重抓哪个物体、从何处接近，再完成原任务 | 优先新增；要保证公开视频真的捕获关键运动 |
| F3 隐藏进度与修复顺序 | 失败前哪些子目标已达成、哪些在失败中被破坏 | 容器内部/遮挡区域使完成状态难以直接判断 | 保留有效进度、只修复失效部分、恢复顺序 | 优先新增；不能只加计数按钮，要有物理修复和最终任务 |
| F4 动作响应与接触适应 | 相同或相近已执行动作产生的不同滑移、迟滞、卡住或运动趋势 | 物性/接触约束在静态末帧不明显 | 抓取几何、退出路径、速度或操作方式 | 研究增量较强、实现风险最高；必须先验证执行器能改变相关动作 |

F4 的目标监督优先写“这次夹持未稳定”“该方向推进受阻”等可证据支持的结论，不要求 VLM 从视频准确报出模拟器隐藏摩擦系数。若总用最大力度或同一动作就能无成本解决全部实例，隐藏属性没有形成有效的决策需求，应修改任务或归入控制组。

每类再按证据难度分层：L0 当前状态足够；L1 记住尝试过什么就足够；L2 必须绑定动作与结果；L3 需要整合多个失败证据、变化与不确定性。主数据不能大部分都是 L1。尤其至少要有两类任务包含“相似动作、不同结果、不同修复选择”，避免一个动作日志反查表解决整套 benchmark。

至少 20% 数据为当前信息充分、历史无增量或历史不足的控制实例。历史已过时的任务需提供合法变化过程，允许模型主动探查；不能人为要求模型凭无法观察的信息猜中。

F1 的未找到目标也可能只是正常探索中的一次未命中。因此当前原型主要证明失败尝试的记忆价值，尚不足以独立代表异常物理故障恢复。论文主体至少还应覆盖两类真实操作失误后的修复，如掉落找回、错误接触退出、恢复被破坏的子目标；不能给普通搜索换一个 recovery 名字。

## 6. 大规模生成：可审计的数据工厂

建议采用“少量经过验证的机制内核 × 有意义的参数变化 × 多源策略实际执行”，而不是让 agent 无限制生成互不兼容的仿真脚本。

```text
任务规范与机制内核
    → 采样场景/隐藏条件（不交给源策略）
    → 源策略实际执行，保存成功与失败全部记录
    → 按预定义事件取得失败历史和可还原锚点
    → 物理有效性、公开证据与可恢复性核验
    → 冻结 split / benchmark 实例名单
    → 从同一锚点执行专家、当前信息与历史指导的恢复分支
    → 保存全部动作、结果、成本和标注
    → 原始失败库 + 训练视图 + 可交互 benchmark
```

### 步骤 A：为每个模板定义信息与动作合同

一份模板规范必须说明：原任务、合法场景参数、不可直接观测但持续有效的条件 θ、候选失败事件、历史中哪段公开证据能减少不确定性、当前输入是什么、哪些修复行动可能不同、最终任务与安全谓词、预算与 reset 范围。

同时写出两个反例：什么情况下当前帧已经足够；什么情况下历史不能区分原因。存在隐藏参数并不自动意味着历史可推断它；能够推断隐藏参数也不自动意味着它影响恢复动作。

模板开发阶段用少量参考控制器验证不同恢复选择的真实后果。有限候选控制器的结果表属于可执行性证据和辅助监督，不是所有合法恢复方案的全集；最终计分仍看原任务，允许模型找到不同但有效的修复。

### 步骤 B：首次动作不得读取隐藏答案

正式构造不再采用“知道目标在中层，故意命令先查上层”的唯一流程。先独立采样 θ，再让盲源策略选择动作、实际执行，随后按规则保留失败。二选一搜索可让初次选择独立于隐藏位置；复杂场景让策略只读真实相机、本体和原任务。

源数据分别标记：policy-native 执行；盲策略/程序安排但由模型执行的探测；执行器或环境扰动注入；专家/脚本示范。后两类不能冒充自然模型失败。注入故障记录实际控制及外部作用，不把原先预测但未执行的动作当作行为证据。

配对可通过独立源执行后的失败事件匹配获得，不要求盲策略在两个隐藏世界都故意选错。匹配和拒绝采样规则先固定，并报告采样产率；不能为了配对把隐藏答案传回源策略。

所有正常成功、构造拒绝和运行错误也进入生成 ledger。失败数分母、自然失败产率和有效信息产率都要能追溯。

### 步骤 C：连续恢复保持真实物理过程

开始采集后，通过控制动作或明确声明的物理环境动力学产生变化。不能在 episode 中改写物体 qpos，让“最后帧看起来一样”。需要关门/回位时优先让机器人执行并记录，或使用在任务开始前定义好的自闭结构；涉及外部帮助时单独标记和评分。

主连续赛道不要求所有不同世界的末帧逐像素相同。先保证同一失败锚点内不同方法起点相同；另建严格匹配子集检验捷径。自然连续状态的微小差别要量化，不能直接宣称观测完全一致。

### 步骤 D：源实例准入与冻结

准入依据为：物理状态有效、事件确为所标类型、任务/历史/当前状态一致、公开证据确实存在、参考专家能从该状态完成原任务。这里的可恢复性是“被参考专家实际验证”，不声称穷尽所有物理可恢复状态。

参考专家可使用私有场景信息来提供执行可行性见证；它是 evaluator 上界，不是可部署教师。公开历史教师必须隔离这些私有信息，无法从公开输入判断时应输出 unknown 或主动探查。

先在开发集固定模板、参数范围、准入规则、预算和 split，再生成并冻结测试实例。不能在测试后删除我们方法失败、baseline 成功或历史收益小的例子。少数专家失败但可能可恢复的构造记录保留并单独统计，避免把专家能力限制隐藏为物理不可恢复。

### 步骤 E：公开证据标注

用隔离的标注进程，只提供匿名 task、RGB、实际动作、本体和统一失败反馈。先生成并封存 current-only 指导，再生成 history 指导；两个上下文独立。源策略内部提示、私有物性、恢复未来帧、hidden-goal BDDL 与带答案的路径不进入教师输入。

输出 evidence_span、attempted_action、observed_effect、supported_belief、unknown、next_instruction、expected_observation。区分观察事实、可能原因和私有真值。自动核对时间片段与行为是否匹配；对测试集作分层人工/强教师复核，所有冲突和新机制风险例全量复核。

训练集每条失败先提出 3 个不同恢复策略，必要时加 1 个 current-only 策略，从相同锚点分别执行。仅改变语言表述的多个版本不是新场景；先保证策略差异与执行可行性，后做措辞增广。

### 步骤 F：执行后分别标注三种正确性

1. 历史解释是否被公开证据支持。
2. 指令是否属于执行器可用的动作/技能范围。
3. 物理执行是否完成原任务、用了多少成本。

解释正确但动作失败可用于证据抽取训练；最终成功但起初解释错误的分支不能直接当正确解释的 SFT 正例。成功恢复对只按真实环境目标验证，不用教师说“成功了”代替物理检查。WAM 想象的视频不替代仿真实际渲染帧。

### 步骤 G：自动审计与导出

- 所有源样本：N 个实际动作对应 N+1 帧/本体观测，时间一致；源轨迹逐动作和已记录外力重放；恢复起点与快照一致。
- 所有恢复分支：初态哈希、预算、采样种子和模型版本可追溯；末状态重评原任务；保存成功和失败。每模板先全量抽检少量恢复的完整重放，之后至少抽检 5–10%，高风险机制增加覆盖。
- 观测匹配：严格子集检查全部公开输入，包括图像、任务文字、本体精度、任何计数器；其他数据报告差异和当前输入泄漏探针结果。不要靠漏给当前策略重要的合法传感器来制造难度。
- 当前输入探针：以未见场景分组测试图像/本体/元数据是否能解码隐藏分支。高于机会水平就排查捷径；探针失败也不等于数学上证明完全不可辨认。
- 私有与公开数据分开；文件名、源指令和 metadata 不泄露目标。完整原始分辨率建议 256×256 起，模型适配的 128/224 输入另外明确；关键运动必须在允许的采样方式下可见。
- 发布前从干净环境重新安装并重放样例；固定代码、资产、模型与依赖，生成 checksum，冻结后不原地修改。基础代码树缺少 git 元信息的问题在正式版通过干净 checkout 与内容哈希解决。

## 7. 数据集、benchmark 与自然失败分布各自承担什么

受控集是 history-dependent recovery 的 stress test，不是现实失败频率的无偏估计。它负责精确控制信息、动作和隐状态；自然失败集负责检验这些发现能否迁移。

自然数据优先来自现有 π0.5/LIBERO 执行，再小样审计 LIBERO-Recovery 的历史—快照映射，以及 RoboMME 的记忆任务失败。外部环境需单独适配和固定版本，不把跨模拟器 snapshot 当可直接互换。旧数据先用于训练/开发，不立即当未见测试。

先跑约 200 个完整源 episode 估计产率，而不是先承诺自然样本数量。若失败概率为 p_f，失败中合格信息样本概率为 p_i，则采到 N 条需要约 N/(p_f·p_i) 次源执行。例如 0.2×0.3 的产率下，150 条需约 2,500 次源执行；这是计划示例，不是已测产率。自然失败产率低时，要调整任务来源或收缩自然性声明，不能偷偷增加答案相关注入来凑数。

训练库保留失败前缀、专家连续恢复及教师多分支；benchmark 保留所有冻结的合格失败锚点，不要求每个待评模型都能恢复。评测未来轨迹和正确标签不能进入模型输入。正式测试的专家恢复答案不作为公开训练数据；可另提供可重放的审计与受控评测接口。

## 8. 模型与接口：先保证可执行，再讨论信息

主环境沿用已运行的 LIBERO/robosuite/MuJoCo 工作流。当前实测版本为 MuJoCo 3.2.3、robosuite 1.4.1；导入外部资源时按其版本单建环境，不盲目加载外部旧快照。

动作基线优先 π0.5_LIBERO，第二执行器保留当前社区 LingBot-VA Goal。社区权重身份及任务覆盖限制随结果报告。每个新模板先做 oracle 指令/参考控制器试验；若正确指令也无法执行，要通过所有方法共享的训练演示、接口适配或改进任务可执行性解决，不把低层失能解释成“不理解历史”。

同时区分两个接口范围：端到端机器人控制接收观测并输出原生连续动作；固定执行器诊断让所有上层使用同一个冻结 actor、同一工具集合。使用显式运动原语的系统需单列，与语言-only 或裸 VLA 分开报告。子目标 oracle 不进入正式主赛道，除非作为各方法等同可用的特权诊断接口明确声明。

正式版还要移除旧 pilot 为调用技能而使用的额外“放碗”措辞：开抽屉子指令应语义匹配原任务，阶段切换由公开观测监控。若需要微调执行器来获得这种合法接口，就用公共训练 split 训练一个所有方法共享的执行器，再冻结它做历史比较；把零样本原基座作为另一个参考，避免混淆低层训练和历史方法的收益。

上层方法可采用 [Qwen3-VL-8B-Instruct](https://huggingface.co/Qwen/Qwen3-VL-8B-Instruct) 作为起点，独立环境部署并先测视频/动作数值输入。当前帧、直接历史、提取证据三种上层基线使用相同 backbone、恢复数据和训练预算。SFT 优先训练证据抽取和下一步可执行指令，冻结动作模型；LoRA 与显存配置通过小样实测决定，不预先承诺单张 24GB 长视频训练。

信息不足的训练输入应监督合法探查/unknown，而不是移除历史后仍要求精确复述只有历史才知道的答案。若做 history dropout，配套重算这种输入下可支持的监督。强 current-only 基线也要训练/提示主动搜索，不能只是删去历史再让其模仿不可辨认的隐藏目标。

监督匹配还需记录证据标签的使用：增加获得同样教师证据监督、但采用普通总结/直接利用方式的基线，分别消融证据监督和结构化利用。由额外教师标签带来的收益与机制收益分开解释。

RL 不是第一阶段的必要条件。只有 SFT/无训练上限稳定、学生有明确差距后，才对上层指令策略用真实恢复回报做优化；不依赖连续动作梯度穿过冻结 actor。

## 9. 公平对照、输入干预与指标

### 9.1 “无历史”只屏蔽第一次尝试

current-only 方法从同一失败锚点拿到当前观测，不拿到第一次的 H_f。它仍能主动探查，并记住第二次恢复过程中的新观测与动作。不能把它变成永远看单帧、不会更新记忆的策略。

所有方法获得同样动作预算、工具、传感器和重采样权限；恢复预算与剩余预算信息都可见。机器人自主回退也计控制步。相同种子用于减噪，但多阶段调用消耗随机数不同，仍需多种子统计。

历史的载体包括上下文、KV cache、递归状态、外部笔记与 fast weights。比较 H/无 H 时要防止首次失败已残留在其他载体中；跨测试实例不得偷偷累积答案。在线更新方法另记录更新步数与计算开销。

### 9.2 六个主要配置

| 配置 | 内容 | 排除的替代解释 |
|---|---|---|
| C0 继续/等预算再采样 | 原任务、当前起点、保留正常在线反馈 | 单纯再做一次的收益 |
| C1 强 current-only | 同等上层模型和主动搜索/恢复工具，不给第一次历史 | 通用推理、指令分解和再次探索 |
| C2 简短动作—结果日志 | 只给尝试记录，不给完整视频 | 是否只需记住查过哪里 |
| C3 直接完整历史 | 同等训练和调用条件下使用 H_f | 强 baseline 已能直接利用历史的部分 |
| C4 我们的证据方法 | 从相同 H_f 提取证据、维护不确定性，再指导冻结执行器 | 提取/利用机制的增量 |
| C5 最小充分公开证据教师 | 给经核验的简短关键证据，同一执行器 | 提取瓶颈与可执行性经验上界；不当普通部署模型排名 |

廉价的规则日志、retreat/backtrack 基线在适用模板追加。若简单规则能覆盖所有核心任务，应修改论文定位或任务覆盖，而不是不报告它。

另外在固定子集加入一个强通用多模态 agent，提供相同的公开历史和执行工具，实际闭环恢复。它用于检验问题是否仅对弱动作模型困难，与“直接提供正确证据”的 oracle 区分；模型规模和调用成本另报，不把不同计算等级混作公平架构对照。

在开发阶段安排关键片段删除、长度相近的中性历史、动作/视觉通道删除和历史充分性干预。其具体配置与预算在测试前固定。交换到与当前世界不相容的历史只能测误导鲁棒性，不能单靠分数下降声称正常历史具有因果价值。

严格配对组使用两个合法世界/过去，各在自己的世界执行正确历史与无历史条件；检查同一策略是否能在两个分支均正确恢复。该思想参考 CMA，不把它包装成新发明。

### 9.3 指标与统计

- 主结果：各任务/家族宏平均的原任务恢复成功率 RSR@B；B 在开发阶段依据任务与参考专家成本固定，不按哪个截止点让我们差值最大来选。
- 成本：0–B 全预算成功率曲线、失败按 B 截断的平均完成控制数、归一化曲线面积；后两者是紧密对应的表达，不算两个独立发现。
- 行为：选择正确修复的辅助准确率、无效重复探索次数、有效子目标破坏率、安全违规和额外模型调用/token/延迟。只有前提仍未改变且已知不可行的重复才算错误重复；修复前提后的再次抓取不能一概扣分。
- 信息增量：同一 checkpoint、同一失败 bank 的 H 与无 H 差值及配对 CI。该差值是该模型的实际信息利用收益，不是历史的模型无关固有价值，也不是唯一排行榜分数。
- 归因：同一历史可见性下比较训练与资源匹配的方法；同一训练模型做历史干预。不同模型差值的差只作交互分析，不用它单独证明方法优越。
- 统计单位是场景/原始源 episode 组；两隐藏条件、不同恢复分支、接入模式、源策略变体和训练窗口按共享来源聚类。报告至少 3 个推理种子，区分推理种子与训练种子；必要时对方法训练种子另做小规模重复。
- 固定最大预算 rollout 可读出截断曲线，但它衡量的是同一策略在不同截止点的表现；若研究预算感知策略，需显式给预算并单独运行，不能把两种问题混为一谈。

强模型已经饱和时，保留它的高绝对成功率和低成本；不因 H−无 H 差值小而认定它差。也不要求完整视频总优于一条包含相同证据的短日志。

## 10. 规模与数据划分

### 10.1 先做 200 条机制验证集

目标为 4 家族 × 2 模板 × 10 个场景组 × 2 个合法条件 = 160 条核心失败，加 40 条当前充分/历史不足控制，共 200 条。数量是开发目标，不保证所有家族均通过。

先做每个新模板的 10–20 个物理实例，验证证据、修复与可执行性。F4 不通过时先移入拓展研究，不用更多 F1 reskin 假装已经覆盖四类机制。若只剩 F1 可行，应停止把该原型扩成论文主要 benchmark，转向问题诊断/方法辅助实验。

开发集允许分析失败并改模板；不能一边看正式测试结果一边补入更容易让我们赢的场景。目标是至少两类新增物理恢复机制成立，而非只重现抽屉成功率。

### 10.2 论文版本建议目标：1,500 条唯一失败

参考构成：4 家族 × 3 模板 × 50 场景组 × 2 条件 = 1,200 条核心失败，另 300 条控制。这里的“条件”应是影响证据和修复选择的真实变化，颜色和语言措辞不单独算机制。

| split | 核心失败 | 控制 | 合计 | 用途 |
|---|---:|---:|---:|---|
| train | 480 | 120 | 600 | 证据/指令 SFT、恢复演示 |
| dev | 160 | 40 | 200 | 预算、提示、采样与接口校准 |
| ID test | 160 | 40 | 200 | 已见模板，未见场景组 |
| OOD template test | 400 | 100 | 500 | 每家族留出一个未训练模板 |
| 总计 | 1,200 | 300 | 1,500 | 计划目标 |

核心划分的实现：每家族两个训练模板，各 50 组，其中每模板 30 组 train、10 组 dev、10 组 ID test；第三模板的 50 组全部 OOD。每组两条件必须同 split。控制集按对应任务/场景关系划分，不独立打散。

OOD 模板必须改变物体类别、遮挡结构、修复组合或机制实例，不能只是训练模板的新随机种子。源策略版本/行为差异作为另一泛化轴；同世界的多个源策略轨迹按共享来源隔离，不能跨 split 泄漏。更强的留一机制家族验证可作为后续分析，不纳入初版必须完成的训练矩阵。

此外争取独立自然失败测试子集 150–300 条，数量依产率门槛决定并另行报告；它不是上述合成目标的默认已达成部分。它可能揭示受控集结论不泛化，这也是应报告的结果。

完整失败→专家成功恢复可作为已验证可恢复性的见证；自动教师另有多个成功/失败分支。所有分支、不同 reset 版本、时间窗口和语言改写均引用同一个 source_episode_id，不计作新增独立失败。

源历史只存一份，恢复尾段独立存储，通过边界和模式索引组成完整过程。无 reset 的拼接必须核对状态/帧连续；系统 reset 的轨迹必须保留断点事件，不能拼成貌似连续的一段。全长合并视频主要作验收样例，避免大量重复编码。

生成 ledger 记录 attempt_id、模板版本、采样参数、源策略、独立 seed、失败类型、准入/拒绝理由、物理快照与资产 hash、教师标注版本、全部恢复候选及结果。基础设施错误单独重试、原记录保留；任务失败不得不加限制地重跑直到成功再替换。

建议 coding agent 模块依赖顺序：

1. `case_spec` / `template_registry`：任务合同、参数、来源和量化规范。
2. `source_rollout` / `failure_events`：盲源策略执行与失败触发。
3. `checkpoint_codec` / `replay_audit`：复用已有数值快照并增加版本校验。
4. `evidence_packet` / `teacher_annotation`：白名单输入、当前先标注、证据时间定位。
5. `recovery_branch_runner`：同起点多分支、预算、全部执行结果。
6. `split_builder` / `leakage_audit`：以源世界和模板分组，冻结测试。
7. `evaluation_sdk` / `baselines`：统一当前/历史可见性、在线记忆和动作接口。
8. `release_builder` / `release_verifier`：原子发布、独立验收与可移植路径。

这些是待开发模块，不是本轮已经实现的目录。现有代码位于 mus2 `/scratch/zhaoguangyu/wam_scale_20261111`，以已验收的 `release_v2` 和复现支持包为起点，避免修改旧冻结结果。

## 12. 计算、标注与存储预算

### 12.1 从实际记录估算

已完成主试验的 384 个恢复分支，连续组平均 86.8 秒、reset 组平均 83.5 秒；加总分支 wall time 约 9.08 小时。这里是占用 actor 的分支时间，含推理和仿真，不是 GPU 内核实际运行时间，也不包含完整源采集/人工标注。

暂用平均约 85 秒/分支作为当前 WAM、当前 480 控制步设置的排期参考：

| 任务 | 规划分支数 | 对应 actor-slot 小时 |
|---|---:|---:|
| 200 例开发集 × 4 配置 × 2 执行器 × 1 种子 | 1,600 | 约 38 |
| train 600 例 × 4 个教师/当前候选 | 2,400 | 约 57 |
| 主测试 700 例 × 6 配置 × 2 执行器 × 3 推理种子 | 25,200 | 约 595 |
| reset 诊断子集 200 例 × 4 配置 × 2 执行器 × 3 种子 | 4,800 | 约 113 |

以上已经接近 800 actor-slot 小时，尚未计入源失败发现、参考专家采集、VLM 标注、额外消融、自然分布试验和训练。每条轨迹不同预算点由同一个完整 rollout 读取，不再乘 4。

这不是承诺运行时间：π0.5 可能比当前 WAM 快，新任务更长也可能显著更慢；VLM 调用额外增加延迟。8 张卡可用率 50–70% 时，仅这部分参考量就是约 6–9 天的连续作业。先通过 200 例实测更新估算，再排正式测试，避免一开始全量网格。

### 12.2 资源建议

- 先用 4–8 个动作 worker，按当前空闲机器分配；每个配对组固定相同后端。正式结果固定模型/资产/环境版本，保存硬件信息。
- 上层 8B 视频 VLM 与动作环境隔离；长视频训练优先有 48GB 卡或多卡方案。24GB 路径先测试量化/分段推理或参数高效训练，不能默认同一个 WAM 环境直接兼容。
- 强教师约 train 每例 1 次 current-only + 3 个历史候选，再加证据审核；先以本地教师或既有可调用教师测成本和质量，不在未测之前承诺 API 总费用。测试集 oracle 只用于诊断，与训练答案隔离。
- 至少 1–2TB 主工作空间，并预留独立备份。当前主交付包约 6.3GB、普通库约 2.9GB；扩展到数万分支和更高分辨率会远超过只按 1,500 段视频估算的容量。
- 当前 NFS 可用空间为 0；继续使用有配额与安全余量的 host-local scratch、显式跨机传输和校验。不能把同名 `/scratch` 当共享盘，也不要通过删除其他用户数据来腾空间。

95% 是开发流水线的工程健康目标，不允许在正式测试里据此无声丢掉另外 5%；正式集合中每项都要有明确的状态、错误报告和统计规则。发现真实任务/数据无效必须按预先规则修复或发布修订，不按方法输赢处理。

### 值得继续扩大投入的证据

多个家族中，公开历史确实能减少恢复决策的不确定性；参考行动可执行；结果不只由一个日志反查规则或动作模型的语言偏好解释；强主动搜索、预算和动作接口控制后仍有可复现的信息/成本差异；未见模板和源策略下仍存在诊断价值。无需预设我们的学习方法一定赢，也不要求所有家族都出现历史收益。

### 应暂停或收缩 benchmark-first 的情形

- 只能制造“关门后记住另一个抽屉”一类记忆题。
- 关键条件只能从私有参数获知，公开历史没有足够证据。
- 即使参考修复也无法执行，或所有可行修复在不同条件下都一样。
- 收益完全来自额外工具/子目标 oracle、更多重试次数或不匹配训练。
- 简单动作日志覆盖全部核心任务，未见模板结果崩溃，或只能靠查看测试后挑样本形成差距。

这些结果出现时应修订研究问题或将数据作为方法的辅助评估，不靠扩大重复样本数挽救主贡献。

## 14. 论文贡献与写作骨架

建议第一项贡献表述：

> 我们构建一个面向连续机器人操作的失败历史恢复数据集与评测基准，保存从首次操作、失败到物理恢复的可重放轨迹；通过多种失败机制、合法观测匹配实例、强主动重试对照和成本评测，分析失败证据何时能改变修复决策以及减少多少重复试错。

其中多机制、完整恢复、泛化和强对照只有在实际完成后才写为已实现。不要把这句话中的组合直接替换成“首个”，也不要把当前 64 条开发结果写成该正式 benchmark 的盲测成绩。

第二项贡献表述为证据提取与使用方法：从实际动作—结果历史提取可核验、允许不确定性的证据，选择执行器支持的修复操作，在恢复中验证并更新。重点比较同等训练的原始历史基线；仅“VLM 输出语言给 VLA”不作为独立新架构声明。

可支撑论文的第三部分是实证结论：哪些失败当前帧已足够、哪些需要动作—结果绑定、何时成本受益而最终 SR 接近、何时低层能力限制信息收益、对未见任务和源策略是否泛化。负结果属于这部分内容。

论文顺序可采用：问题与已有评测缺口 → benchmark 与生成审计协议 → 强基线揭示的瓶颈 → 证据方法 → 全量/泛化/干预实验 → 限制。benchmark 和方法分别成立；前者不能靠后者的成功样本反向定义。
