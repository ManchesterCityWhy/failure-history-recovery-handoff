## 0. 执行摘要：先读这两页

### 0.1 一句话研究主题

**研究失败前的动作—结果历史，何时能为失败后的恢复提供当前观测没有的决策信息；建设可测量这一作用的 bench，并学习把有用证据转化为冻结 VLA 可执行的恢复决策。**

研究的不是“再试一次能不能成功”，而是“过去的什么证据，为什么让下一步选择更好”。

### 0.2 一项研究，两个方向的贡献

| 方向 | 拟交付内容 | 独立验收问题 |
| --- | --- | --- |
| Bench / 数据 | 完整源执行、失败锚点、可重建现场、成功与失败恢复分支、历史信息干预与闭环评分 | 是否区分了继续尝试、当前状态已足够、历史确有额外作用？ |
| 方法 | 有出处的事实证据构造、消费者条件化的证据收益选择、可执行短指令决策 | 是否优于同数据/同预算的强历史基线，而不只是多训练、多计算或更强控制？ |

不能把“采一批失败”“给VLM视频”“VLM指导VLA”本身当作新颖性；这些都有直接先例。

### 0.3 当前最重要的结论

1. 旧工程已经在真实物理仿真中跑通过 π0.5 → 失败现场分支 → Qwen指导 → 闭环打分 → 数据包装。
2. **尚未得到可靠的历史收益正结果。**自有最新小样本中，current-only 与 true-history 都是3/4成功，只有两个源场景，且失败语义仍有争议。
3. 旧项目没有训练完成我们拟提出的 recovery VLM、证据收益选择器或RL策略。训练方案/配置草案不是已执行训练。
4. 关键风险不只是模型小，而是失败定义、历史信息差和动作可执行性尚未分别建立。
5. 新机器先重建最小可靠闭环与门槛实验，不先复现十个系统，也不直接八卡大训练。

### 0.4 本轮默认技术路线

| 项目 | 默认决定 |
| --- | --- |
| 平台 | LIBERO生态；自建恢复协议，不冒充原LIBERO官方成绩 |
| 执行器 A | 官方 π0.5-LIBERO，冻结；不是从 pi05_base 先训练起 |
| 恢复VLM | Qwen3-VL-2B-Instruct 起步；需要时在独立实验使用更强教师 |
| 恢复起点 | 从统一失败锚点原地继续；不由系统免费把场景复原 |
| 首版动作接口 | 每场景共享2–4条已验证可执行的短指令，选一条，最多作用60步，再交回原任务 |
| 历史表示 | 截至锚点的RGB、实际动作、本体与时间；最多3条有出处的事实记录 |
| 方法训练 | 先监督训练共同决策器R并冻结，再用实际执行结果训练收益选择器S |
| 不做的事 | 首轮不改VLA权重、不自由生成复杂计划、不做多轮RL、不引入力控/相机等额外特权工具 |

有限候选是验证机制的收窄接口，不是最终通用智能体的全部能力；它相较早期“自由生成纠正”的设想，是为控制grounding与归因而作的明确调整。

### 0.5 首轮代理只执行 M0–M2

```text
M0 新机基础栈、真实模型与可复现现场
  → M1 连续源采集、失败审核、首个信息诊断家族
  → M2 同现场候选执行、历史/当前教师对照、门槛报告
  → 关口复盘
  → M3 reader监督训练 → M4收益选择 → M5正式评测 → M6发布
```

首轮成功定义是：可信工程 + 可复核的可行性判断，不是必须得到正收益。第18节有可直接交给coding agent的启动指令。

## 1. 我们为什么一步步收敛到这个问题

### 1.1 最初设想与保留下来的核心

起点是：第一次失败不应该完全浪费。机器人可能已看到物体落在哪里、哪个动作没有产生效果、接触如何改变状态；这些经验可能指导下一次操作。

后续讨论纠正了几个过强前提：

| 早期想法 | 现在的严谨表述 |
| --- | --- |
| 完整失败视频一定比最后一帧好 | 对理想决策者，额外可忽略信息不降低最优可达上界；有限模型可能被噪声、错误总结和分布偏移误导 |
| 失败分析正确就能恢复 | 分析、决策与动作执行是三个不同能力；语言合理不等于π0.5执行得出来 |
| 只用失败样本评恢复即可 | 需要共享固定失败集；每种policy各自筛失败，会产生不同难度分母 |
| 训练后历史增益更大就说明机制成立 | 跨模型差值混有训练与基础能力；还需同模型干预、强训练基线和事实级控制 |
| 多生成几条GPT纠正就是新数据方法 | 这是合理增强/蒸馏，但teacher—验证—再训练已有很近的先例 |
| 不能反传穿过VLA，所以只能RL | 可直接用真实执行结果做监督；RL不是不可微系统唯一的学习方式 |
| 做一个专门历史必需bench就足够 | 受控诊断有价值，但必须分开报告自然失败覆盖率、当前充分控制与外部泛化 |

保留的核心是：**用真实、可观察、与当前恢复决策相关的历史证据，而不是泛泛的失败故事。**

### 1.2 研究问题与假设

- RQ1：哪些可恢复失败存在“当前输入不够、过去交互提供额外线索”的信息结构？
- RQ2：现成或直接历史训练的模型，是否能把这些线索用到正确决策，而不是仅改变输出？
- RQ3：显式证据与决策收益监督，能否提高成功率、鲁棒性或计算效率？
- RQ4：历史什么时候无益、过时或有害，模型是否应忽略它或重新探测？

待验证的工作假设是“某些场景可获益”，不是“所有任务必须依赖历史”。历史的价值依赖当前传感配置、剩余预算、允许动作、隐藏状态和消费者能力。

### 1.3 更本质的形式化

锚点物理状态记为 s，模型当前合法输入为 x，过去交互为 H，剩余预算为 B，候选恢复决策为 c，固定actor为 A。

```text
c = R(x, E(H), B)
Y = Execute(A, s, c, B) 的原任务成功结果
```

同一x可能对应不同未观察到的状态；历史有时能降低这个歧义。即使知道隐藏事实，也可能因为A不会执行或B太小而无法提高Y。

因此要拆开：信息存在 → 信息可提取 → reader能利用 → actor能执行 → 闭环完成。任一环失败，都不能笼统解释为“failure learning不成立”。

如果只有普通成功/中性交互也能产生相同收益，结论应是“恢复使用交互记忆”，而不是“失败比成功有独特信息优势”；后者需要额外对照。

## 2. failure、recovery和reset的统一定义

### 2.1 failure不是“任务暂时还没成功”

建议将五类状态分开标注：

| 状态 | 定义 | 是否进入确认失败主集 |
| --- | --- | --- |
| operational_candidate | 规则发现空夹/失去接触等疑似异常 | 不自动进入 |
| confirmed_failure | 已尝试局部操作未达到应有效果，或破坏了必须保持的状态；有审核依据 | 可以，另审核可恢复性 |
| normal_transition | 正常放置、释放、接触切换等 | 否，作为误触发/控制 |
| uncertain | 可见证据不足，无法可靠判断 | 单列，不制造确定标签 |
| terminal_unrecoverable | 任务规则已被不可逆违反，或当前接口/预算无法继续 | 单列，不悄悄删除 |

局部目标需由任务、阶段和观察支持。接触丢失本身不等于掉落；工具升高不等于物体升高；任务最终超时也不说明每个中间事件都是失败。

失败真实性、信息需求、可恢复性与历史有效性是不同字段，不合并成一个“好样本”标签。审核不得根据本方法是否获胜倒推。

### 2.2 recovery的本轮含义

恢复是从异常后现场出发，让原任务最终在约定预算内成功；可能要重新接近、重抓、打开遮挡、纠正物体位置。不要求精确回到失败前状态，也不要求做严格逆动力学。

“回到可继续状态”是功能性恢复，不是把场景全部倒带。底层动作仍来自同一个冻结π0.5；若使用脚本运动原语或遥操，它们是独立控制权限，必须另标注。

### 2.3 四种容易混淆的reset

| 设置 | 谁做、改变什么 | 如何计分 | 本轮用途 |
| --- | --- | --- | --- |
| 原地继续 | 机器人从失败现场操作，系统不整理物体 | 使用原任务剩余预算；恢复动作均计费 | 主设置 |
| 机器人自主恢复/回位 | 机器人实际移动、清理或重抓 | 实际动作与时间计费；不保证复原所有物体 | 可包含在主设置中 |
| 外部机器人回位 | 仿真赋值机器人关节，物体保持 | 外部帮助必须显式报告，不能称自主回退 | 仅不同协议的对照 |
| 全场景reset后重试 | 系统把机器人/物体恢复初始状态 | 单列attempt budget与跨尝试规则，不能冒充一次初始化成功 | 后续扩展，不是本轮主分数 |

评测器为不同方法重建同一失败现场，是发同一道题，不是给同一方法免费多次机会。每个正式方法/seed rollout仍只有一份预算，期间reset_count=0。

### 2.4 reset后什么历史仍有效

物体身份/材质等持久属性可能仍有效；失败后的空间位置、抓取状态、已经完成的阶段可能因reset失效。若系统同时重采隐藏物理参数，前一次证据甚至可能不再适用。

所以不能笼统说“从失败学到的信息能用来reset”。本轮优先原地恢复，避免同时研究证据持久性、全场景reset规则和多次累计成功率。

## 3. 已有工作的图景：哪些成熟，哪里仍有空间

### 3.1 合理分类：多轴而非一棵互斥树

训练/执行、是否更新权重、是否物理回退、是否外部reset是不同维度。同一方法可以离线训练、上线冻结，同时自主恢复；不能把“训练类”与“执行类”当成绝对互斥。

| 类别 | 主要思路 | 最相关代表 | 对我们的约束 |
| --- | --- | --- | --- |
| 离线恢复数据与模仿 | 专家纠正、扰动桥接、自然失败后补示范 | RACER、CARE、FLARE、REBOOT | 采失败—恢复数据本身不新 |
| 历史直接条件化/记忆 | 将失败帧、动作、状态或latent记忆喂给策略 | RoboRetry、Zeva、RoboTTT | 不能声称首次利用第一次失败 |
| 外层监督与harness | 监测、诊断、纠正、验证、交回策略 | Spotter、RACER、ViFailback、Harness VLA | VLM+冻结actor与恢复循环并不新 |
| 测试时策略适应 | 利用失败动作价值/偏好在线改变策略 | FAR | “失败后改变策略”不是新命题 |
| 视觉目标/熟悉状态恢复 | 选择可达里程碑，回到策略熟悉区域 | B2FF、CoRe等 | 需要对应动作接口，不能假定π0.5原生支持 |
| 简单物理退回 | 逆序运动、抬升、回位再继续 | Backtrack、SPR、simple-retreat对照 | 很便宜的动作也可能改善成功，必须比较 |
| 结果/价值引导记忆与预测恢复 | 用结果学习保留经历或选择未来 | OnEvoMemory、ForkCast | “按收益选证据/候选”也不能笼统称首创 |
| 恢复/记忆评测与归因 | 固定失败状态、历史需求、事实级干预 | LIBERO-Recover、RoboMME、CMA、IMEP | 首个恢复bench/历史bench/历史反事实审核均不能作为主张 |

成熟的是数据增强、层级纠错、失败检测/回退与恢复状态测试等方向；相对更值得细化的是：历史里真正提供了什么信息，如何从动作后果提取，如何证明它指导了正确恢复，而不只是引起行为变化。

这些短板并非都不可解：监督不足、控制接口不适配和评测混杂可通过实验设计改进。但不可观测状态本身、不可逆破坏和执行器能力边界不能靠语言分析消除。

| [ForkCast论文](https://arxiv.org/abs/2610.18650) | 比较commit/reobserve/replan的预测未来，冻结VLA | 候选恢复排序已有；我们的待证差异在真实历史证据的边际决策收益 |

早期清单还覆盖VBT、RaC、Genie Centurion、Phase-Conditioned IL、Dream2Fix、EgoRecovery、CARE、ReCoVLA/ForceRFT、REFLECT、RoboFAC、PhysMem、See Plan Rewind、Back to the Manifold、RecoveryChaining、ProbeAct等。它们可归入上表相邻路线；本交接不为未重新核实的名称补造论文链接或实现结论。新代理先深读最接近的工作，其他作为补充检索，不以“列表更长”代替定位。

REBOOT收录遥操/专家恢复，失败采样参考策略错误分布；不能把所有失败都称为policy自然产生。RACER恢复多由专家与扰动流程构造；标签可能依赖privileged场景描述，不能不加审核直接当公开视觉证据。

已有数据可用于预训练、格式借鉴或外部验证，但没有一项可以未经审计就同时提供“我们的actor、自身自然失败、完整前缀、严格现场、多个候选真实收益、无泄漏测试”。这也是自建协议的理由，而不是已有数据无价值。

### 3.4 创新落点与不能作的主张

可争取的具体增量：

1. **恢复证据诊断数据**：自然失败覆盖 + 受控信息差 + 当前充分控制；保存证据来源、同状态动作分支及干预，不只保存成功视频。
2. **消费者条件化的证据收益监督**：在固定R与A下，学习哪些事实能改善当前恢复选择；失败低回报片段也可能有高信息价值。
3. **完整证据链验证**：历史事实 → 决策变化 → actor实际动作 → 任务后果，并展示不需要历史时的行为。

但CMA/IMEP已研究归因，OnEvoMemory已研究价值记忆，ForkCast已研究候选恢复，Spotter/Zeva已有接近系统。**上述三项是待检验的研究定位，不是“保证绝对首创”。**投稿前必须逐项查新与强基线对比；若目标/标签/实验已被覆盖，应调整贡献，而非换名字。

### 5.5 重建踩坑是比旧分数更重要的迁移信息

可以说：真实VLA恢复闭环和可审计数据协议具备工程可行性；弱历史提示并没有自动奏效；存在必须拆开的语义、信息与执行瓶颈。

不能说：历史已被证明有效；我们的方法已训练；已实现SOTA；已完整复现上述论文；已有可正式发布的历史必需bench；旧测试通过就表示新机可运行。

## 6. Bench设计：数据从哪里来、怎么变成题目

### 6.1 一条数据的完整生命周期

```text
任务初始化 → 原任务真实执行 → 可疑事件记录（源执行不中断）
    → 源任务成功/超时/错误记账
    → 离线重建候选现场 → 失败语义审核 → 建立固定case
    → 同现场执行多个候选恢复 → 保存成功/失败/错误后缀
    → 证据审核与训练标签 → 根场景划分 → 数据包与独立评测
```

一条完整分支是“源前缀 + 某次真实恢复后缀”，不是把源轨迹后续和另一条成功视频随意拼接。边界当前观测只保留一次。

### 6.2 两条轨道分开建设

| 轨道 | 来源 | 研究用途 | 必须承认的限制 |
| --- | --- | --- | --- |
| natural | 固定π0.5正常执行，无人为坏动作 | 真实失败分布、覆盖与部署相关性 | 失败率可能低，当前可能已足够 |
| controlled_diagnostic | 明示规则的真实物理前缀，可含脚本源策略 | 控制信息差与恢复分支 | 不是π0.5自然自失败；不能用视频生成/teleport假装真实前缀 |

自然源actor与恢复actor默认相同。固定录制前缀让所有方法共用分母；最终仍需在线自身失败测试，防止把固定题库效果扩大为完整部署能力。

### 6.3 连续采集：不能重复旧collector的偏差

旧collector一遇首候选就截断，因此源后续结果被删失。新版本记录事件后继续原policy，直到任务成功、600步预算或错误；每源最多2个锚点、间隔至少60步，同源锚点仍属同一统计簇。

live source遇候选时只保存未扰动的状态/观测缓存、已执行动作、策略查询/未执行chunk信息；不试探、不清队列、不额外刷新传感器。不应在live source做canonical forward/probe，否则“记录候选”可能改变源轨迹。

源结束后在副本重放至锚点，建立canonical观测和snapshot/probe。保存raw与canonical观测对应hash。源未来只给curator审核，不给恢复模型。

### 6.4 审核与样本纳入

自动触发 → 盲化审核短片 → 局部操作/预期效果/实际效果 → failure状态 → 信息充分性/可恢复性 → 现场校验。

锚点已满足全局任务成功的，不作为失败题；到原预算末尾才发现的超时也不能再免费补一份600步进入主设置。首版沿用最早60步、至少剩余180步的候选窗口作为开发默认，窗口外事件与预算不足单列覆盖统计；调整窗口需新配置预声明。

审核人不看方法谁赢。人类尚未审核时写provisional，不伪造金标。privileged真值可给curator判断物体是否实际掉落，但公开事实必须可由合法传感证据支持。

保留所有源成功、无事件、正常接触、争议、不可恢复、加载错误和未采完情况，逐层报告产率。最终测试不能按“history比current强”或“我们赢”筛选。

### 6.5 第一批任务：可执行的遮挡/位置历史

优先做“物体先可见，随后错误进入某个当前遮挡的合法区域”，例如两个可操作抽屉之一。先验证π0.5能分别执行开上/下抽屉等候选，再建设物理前缀。

历史中应能指出最后可见位置与后续移动；锚点当前front、wrist、本体、任务与候选集合不能泄漏答案。若从当前任何合法视角已可辨认，就不能称历史必需。

允许current-only在预算内主动搜索；不人为设置“一次选错即结束”来放大历史优势。一击决策诊断可以单列，但不是正常闭环任务规则。

第二家族再考虑接近方向/操作方式受阻的可见交互效果。空夹vs滑脱不必然对应不同最佳恢复，必须真实候选验证。质量/摩擦/刚度推断暂不主打，没有力觉或足够可见运动就不能臆造物理标签。

### 6.6 同现场与同当前输入不是一回事

- 同一case跨方法：完整物理现场、当前输入、actor、队列清理、预算、seed规则相同。
- 不同历史的诊断twin：模型当前输入可相同/近似，但隐藏物体位置可能不同；不能同时声称完整隐藏状态也相同。
- 跨twin匹配覆盖所有公开输入，而不是只看front像素。不能通过文件名、候选ID、数量、绝对时间或task文本偷偷传递答案。
- 近似匹配标准在看结果前冻结；不满足严格匹配就叫近似诊断，不冒充CMA式严格证明。

### 6.7 划分与独立样本

根组绑定任务家族下的布局/资产/构造recipe根。同一组的隐藏变体、微扰、twin、所有seed、锚点、候选、措辞必须同split。

不把整个任务家族全部当唯一组，也不按seed细拆“独立场景”。可另留整个family作强迁移。所有开发/接口反复调试过的场景永久留development；旧两个case不能改名进入test。

正式train/val/test按组预先冻结；70/15/15是参考比例，不是样本不足时强行切三个小集合的理由。最终test需未被研究者用来选题/调参的新组。

## 7. 方法规格：E、R、S和冻结actor

### 7.1 总体信息流

```text
H（公开已执行历史） → E（事实候选，带出处）
                          ↓
x、预算、候选指令 → S（预测证据集合对固定R的收益）
                          ↓ 所选事实，允许空集
                      R（共享指令评分器）
                          ↓ 一条短指令c
               冻结π0.5（只读当前观测与c）
                          ↓ 实际动作与任务结果
```

E初版不强求训练；R先学会读事实并选择可执行操作；R冻结之后再学S。不要同时改E/R/A，却把旧收益标签视作同一监督。

### 7.2 输入输出边界

| 模块 | 输入 | 输出 | 首版参数状态 |
| --- | --- | --- | --- |
| E | 历史图像、实际动作、本体、时间、任务 | 最多3条事实及支持frame/action引用 | 规则/冻结VLM草稿，可人工审核 |
| R | 当前双图、本体、任务、预算、证据集合、候选c文本 | c的成功评分，选择argmax | Qwen LoRA+二分类头，先训后冻 |
| S | 当前输入与候选证据集合的冻结表征 | 空集/单条/全集之一 | 小型收益预测器，R固定后训练 |
| A | 当前front/wrist、本体、所选英文短指令 | 连续动作chunk | 官方π0.5-LIBERO全程冻结 |

冻结actor只保证权重不变，不保证系统正常任务能力不被错误介入损害；误触发和坏指令仍需在线测。

### 7.3 E：提取观察事实，不编失败故事

每条事实至少包含时间区间、动作、实际可见效果、对象可见关联、支持引用和不确定性。观察与解释分字段。

“物体最后出现在上层入口，随后被板遮挡”可以是事实；“现在应打开上层”属于R的决策，不写入事实字段。看不清的对象写unknown，不能用仿真隐藏ID冒充视觉识别。

每条最多2张支持图、64英文词；3条最多6张历史图，加当前2图。保留有序动作摘要、夹爪变化和本体差异；均值可能抹平接触事件，应有可追溯原序列。归一化控制命令不解释成米/牛顿。

完整历史仍存磁盘，6图只是推理预算。E不得看未来成功视频；语言草稿不是金标。需要更强教师时先作为独立上界，不因其有特权就混入普通方法结果。

### 7.4 候选集合：控制grounding混杂

每家族2–4条短英文指令，含continue保守选项，建议≤24词。来自预声明模板或只读当前输入的构造器，不能读历史后才把正确答案新增到候选菜单。

候选顺序与正确答案无关地平衡；ID不编码答案。每条作用60控制步，随后清空队列，回到原任务。所有方法共享这些权限；π0.5不读证据、收益、推理和privileged标签，只读所选指令。

若π0.5不能执行某候选，先缩小家族或接口。共同能力微调需所有方法共享、另立版本；脚本技能是混合控制实验，不能伪称冻结VLA本来会做。

### 7.5 R：共同消费者如何训练

对每个case i和候选c，用固定A从同一s执行多个seed z，得到成功结果Y_i(c,z)。R对 `(x_i, S, c)` 评分，默认二分类头接最后有效文本表征，sigmoid输出成功概率。

```text
q_target(i,c) = mean_z Y_i(c,z)
L_reader = BCE(R_phi(x_i,S,c), q_target(i,c))
```

头与语言LoRA一起训练，视觉编码器冻结。多图processor、chat template与位置编码用官方实现。若用success/failure token概率替代评分头，必须单独验证token化和归一化，另记接口版本。

训练记录包含公开输入引用、证据集合、候选文本、成功数/执行数、branch引用、根组。后面的结果/分组字段只给trainer，不进prompt。可混合有证据与null输入；无历史确实无法辨认的标签歧义是正常现象，不能通过case ID解除。

强current-only与raw-history基线获得相同训练split、候选结果与训练预算；不能只比未见过这种格式的冻结弱模型。

### 7.6 S：消费者条件化的证据收益

固定E、R、A、候选、时长与预算。记c_i(S)为R读证据S后的选择，c_i(empty)为同一个R无历史的选择：

```text
Delta_i(S) = mean_z [Y_i(c_i(S),z) - Y_i(c_i(empty),z)]
```

这不是摘要准确率，也不是源轨迹回报；它是证据通过改变该reader选择而产生的经验收益。低回报失败片段可能提供好证据，成功片段也可能对当前决定无用。

第一版只比较5类集合：空、e1、e2、e3、全部；缺失项固定mask。冻结Qwen表征，训练两层MLP（例如hidden256、dropout0.1）预测Delta，先Huber回归，明确差异时可加ranking loss。维度从模型获取，归一化只拟合train。

S的特征须包含当前输入、该证据集合，以及共享候选文字的公开表示；可按 `(x,S,c)` 提取冻结R表征后做集合聚合。candidate ID/顺序不得编码答案。特征缓存绑定reader/encoder/processor和输入hash，不能复用其他reader或test拟合出的表征归一化。

约束：

1. 同一候选固定执行的回报不会因为证据文字改变而改变；R选择相同c时，此定义Delta=0。
2. 换R后标签失效，要重新计算；actor、候选措辞/窗口/预算改变也需核验。不能默默沿用旧标签。
3. 3个seed标签粗糙，保留原结果与平局/不确定，不强制排出“最佳事实”。
4. S只传事实给R，不传收益标签、答案ID或额外选择码；null是合法选项。
5. current-only须屏蔽E/S全部历史路径，不能让S先读历史再暗示答案。
6. R若不会用正确事实，收益标签可能全0；先过reader能力门槛，不期待S自动解决。

逐集合编码先用于工程，成本可能超过all-facts。selector读全历史/全部候选的成本也要计入，不能只报R少读token就称高效。后续共享编码是另一个可测试优化。

### 7.7 结果表复用的合法范围

固定 `(case,c,seed,A,B,query schedule)` 可只执行一次，形成候选结果表。冻结R在不同证据条件下选c后，查询该表构造标签。

必须验证同一指令文本hash、窗口、handoff、预处理、queue与seed规则；变成动态纠正/多轮策略后，不能默认复用。复用是离线标签计算，不是新物理试验，也不能算更多独立样本。

正式主结果在冻结test上fresh执行各方法选择的闭环策略；表复用另做预先指定的fresh校验。利用结果挑出的best-of-K只能作候选能力诊断，不能当可部署教师或无偏上界。

### 7.8 本轮训练选择：SL/SFT优先，不先RL

| 方式 | 数据 | 本项目位置 |
| --- | --- | --- |
| training-free教师 | 公开失败前缀/当前输入，先封存决策，再执行验证 | 验证信息与actor门槛 |
| reader监督训练 | 候选真实成功/失败/代价 | 主线；梯度不需要穿过VLA |
| E监督/蒸馏 | 经审核且仅用合法信息的事实与时间出处 | 可选；不把生成理由当真因果 |
| S收益训练 | 固定reader下的Delta及依赖hash | 具体方法探索 |
| DAgger-like聚合 | 学生遇新现场→教师标注→真实验证→聚合 | 初版会跑之后扩量，不是首轮前提 |
| RL/bandit/偏好 | 真实回报、安全/步数/调用成本 | 有明确SFT剩余瓶颈后另立实验 |

成功恢复后缀先用于构造上述监督与审核，本轮不微调π0.5。未来若做actor BC，失败动作只作上下文，不能不加区分当正向动作target。

同失败的5–10条语言释义是增强，不是5–10个独立case；继承同一split，换措辞是否仍有效需检验。

### 7.9 起步训练配置（待实测，不是已跑值）

Qwen3-VL-2B、语言LoRA r8/alpha16/dropout0.05、评分头训练；lr1e-4；batch1/grad accumulation8；最长3072 tokens；梯度检查点；硬件/算子验证后bf16。先3步forward/backward显存smoke，再≤500 updates，seed7；最多保留2个adapter checkpoint。

所有模块名、processor行为与显存需实测；不盲复制不匹配层名。20个train case过拟合只验证训练器；约30独立case只做pilot，正式收益可能需要数百组，由学习曲线与功效分析决定。

## 8. 数据格式、安全边界与发布契约

### 8.1 三个访问域

| 域 | 内容 | 访问者 |
| --- | --- | --- |
| policy_inputs | 截至锚点的历史、当前双图/本体/任务/预算、候选文字 | 模型 |
| evaluator_assets | 完整快照、场景/隐藏参数、成功判定、重建recipe、probe | 独立评测器/curator |
| recovery_supervision | 未来恢复后缀、结果与收益标签 | 训练split的trainer；test对应内容不开放 |

分目录不是恶意访问防护；正式test应隔离进程/容器，只传allowlist，不能把真值/未来文件系统挂给模型。

### 8.2 数组与时间对齐

| 字段 | 形状/语义 |
| --- | --- |
| front / wrist | `(T+1,H,W,3)` uint8，标清原始/模型图预处理 |
| proprio | `(T+1,8)`，EEF xyz、axis-angle、两指状态 |
| actions | `(T,7)`，实际执行命令，不是未执行预测chunk |
| time_s | `(T+1,)`，递增控制时间，初始化准备另记 |

观测i只能用actions[:i]解释，不可看actions[i]及未来。NPZ不启用pickle；大数据可分chunk，但需要稳定索引与校验。拼接prefix+suffix去一份边界帧，继续满足T+1/T。

索引元信息不整包送模型。case ID、split、cohort、根组、审核标签、文件路径都不进入预测。

所有预声明源结果、失败与成功分支、加载/模型错误、审核争议、无历史即可解决、历史有害、无可行候选的病例均留痕。训练可做明示采样，不能删除原始负分支后把数据宣称为完整分布。

manifest覆盖原始资产和生成索引/标签等元数据；manifest自身可用外部digest签名/记录。发布前提供数据卡、许可、根组划分、可复跑小样例、完整审计与future隔离说明。

旧π0.5-LIBERO收据记录16个对象、12,439,085,481字节，norm_stats SHA256为 `b3a44bb2810436fb62917decaea58bd4d9110255df527dea21e8fd40c960bd84`。这些只定位旧版本；官方发布更新时，不应假定对象数永远不变。新下载有新manifest，差异需注明。

若网络需要镜像，只用可核对官方对象/发布哈希的来源，记录上游与传输来源。`.partial`、只有README、能import都不算完整部署。下载失败不得换随机权重或伪装模型成功。

### 9.6 模型与仿真smoke顺序

1. actor用合成合法输入真实推理，确认shape、有限值、seed重复；合成图输出不证明任务能力。
2. sim创建一个官方场景，渲染front/wrist、执行几步、检查动作与本体语义。
3. actor接sim完成一条原任务，检查真实反馈，不是脚本专家代执行。
4. 小网格部署基线至多8条；固定任务/初始化/600步，不按结果挑演示。
5. 保存一个新机现场、跨进程重建、相同动作probe，验证后才开始恢复分支。
6. Qwen读实际场景的当前双图与历史样例，核对processor确实接收图像、mask与时间，不能只跑纯文字示例。

首条任务失败不能直接归为环境坏或模型没能力；核对图像180°旋转、尺寸、状态姿态表达、归一化、7D动作、执行前缀与初始化。修正后另起配置记录，保留失败日志。

### 9.7 八卡使用策略

M0只用1卡actor，需要时另1卡VLM；渲染实际占哪张卡要监测。通过后按1→2→4个独立worker测试分支/小时、显存、CPU/IO，确认扩展效率再用更多卡。

每个actor进程启动时仅暴露计划分配的一张卡，避免JAX自动看到八卡并预分配显存；实际可见设备数与分配策略写入启动收据。

每个actor worker独立端口/队列/RNG。若对共享policy对象逐query重置RNG，必须串行/加锁，防止并发请求互相改seed。不能把八个客户端发给单个串行服务就声称实现八卡并行。

逻辑卡编号与GPU UUID都入日志；不硬编码GPU0必空闲。loopback服务默认只监听127.0.0.1；跨机访问另做明确安全配置，不直接公网开放。

## 10. 现场重建、动作与预算的硬契约

### 10.1 统一控制接口

默认复制旧已验证语义：双视角当前RGB，模型侧224×224与官方朝向；8D EEF/夹爪状态；7D归一化控制；预测10步、执行5步再规划。新版本若输出horizon变化，显式记录，不偷偷截取错误维度。

总控制预算600，静置10步单列；恢复预算为600减锚点实际控制步。纠正窗口60，之后原任务。主score用环境原始成功谓词，不用VLM自评；simulator不得自动reset掩盖失败。

原指令继续B0也从canonical锚点清队列重新接入。源执行未中断的未来可能带旧chunk/不同query流，只用于审计，不能直接替代B0。

控制步/模拟时间与推理wall time分别报告。离线仿真等待VLM时暂停物理不代表真实机器人安全实时运行；不要以“20Hz控制接口”宣称模型20Hz推理。

### 10.2 重建recipe，而非XML roundtrip

保存原BDDL/场景编译输入、资产hash、官方初始状态索引/内容、env seed、settle动作、已执行前缀及必要状态。重放后恢复控制器、夹爪、observable缓存、RNG、计数器等影响后续状态；只存qpos/qvel不够。

自定义场景通过TaskAdapter提供初始recipe、资产/参数、编译版本、任务成功及局部审核接口。禁止把导出XML当原场景参数。只对可信官方初始化资产使用必要的兼容反序列化；外来snapshot不允许任意pickle。

### 10.3 新机内验证门槛

以下沿用为新机开发初始阈值，对新机生成的case校验；不是要求新机重渲染旧图片相同：

| 校验 | 默认阈值 |
| --- | --- |
| 前缀重放flat物理状态 | max abs ≤1e-10 |
| 当前front/wrist重建 | 每视角RGB MAE ≤1个uint8等级 |
| proprio | max abs ≤1e-6 |
| 独立8步固定probe的完整状态 | max abs ≤1e-7 |
| 同case正式方法起点 | flat/current RGB/proprio的start digest完全一致 |

probe在独立副本执行，不给正式策略免费动作/新观察。跨机旧case不兼容就单列，不为了“复现旧结果”放宽到通过。新栈若确需不同阈值，在看方法胜负前建立协议新版本并重新校准，不能后验调阈值救成绩。

校验失败隔离整个case，所有方法统一排除，记录覆盖损失。方法运行超时/格式错误另计pipeline非成功，不能混成重建错误。

## 11. 评测矩阵：如何回答学长提出的归因质疑

### 11.1 不要求不同模型的无历史成绩一样

“baseline 20/40，我们30/70”无法单独归因历史机制；但也不意味着任何相减都不科学。固定同模型、同起点、同预算的输入干预是可解释的配对实验。

采用两个轴：训练方案/方法 × 信息条件。主结论分开写：

| 问题 | 控制方式 | 结论范围 |
| --- | --- | --- |
| 固定模型是否受益 | 同checkpoint，current与history干预 | 该模型在该数据分布的输入效果 |
| 方法是否优于普通训练 | 同数据、基座、训练资源、历史、actor与预算 | 整体方法比较，不把差值自动称严格因果 |
| 是否用对具体事实 | 固定模型，删关键事实、保持事实释义、合法事实替换、精确重复 | 事实特异性、稳定性与决策正确性 |
| 是否只是再次尝试 | 原指令/通用retry/简单退回，同剩余预算 | 排除更多机会/更多动作解释 |
| 是否影响真实部署 | 自身actor在线失败、检测与恢复介入 | 总成功、误介入、成本与泛化 |

fixed-case的条件恢复率q不能直接与另一policy独立筛出的失败q比较。总成功 `p+(1-p)q` 也只有p/q来自一致总体与协议时才有意义；不能默认独立重试套 `1-(1-p)^2`。

### 11.2 必须建立的基线

| 编号 | 方法 | 用途 |
| --- | --- | --- |
| B0 | 原任务指令继续 | 自然重规划/随机重试收益 |
| B1 | 固定generic retry | 排除任意改prompt就有效 |
| B2 | 等预算简单退回/抬升再继续 | 排除通用脱困，不冒充Backtrack全文 |
| B3 | 同数据训练的current-only R | 强无历史对照 |
| B4a | 同数据训练的raw-history R，均匀采样 | 实际直接历史基线 |
| B4b | 同数据训练的raw-history R，与E完全相同支持帧/动作窗口 | 区分关键帧选择与事实组织 |
| B5 | 固定共同R + 全事实 | selector是否必要 |
| B6 | 固定R + 随机/相关性选择，匹配条数和输入预算 | 区分收益选择与普通压缩 |
| Ours | 固定R + 学习式收益选择S | 方法主项 |
| Diagnostic | 合法教师、人类事实、privileged best-of-K分开 | 定位信息/reader/actor瓶颈；特权项不列普通排名 |

简单退回若π0.5不跟随，可以单列scripted控制对照，动作计费、权限明示；不能对本方法加脚本而其他方法没有。不要只用未训练2B作为唯一对手。

所有训练方法拿到相同train的候选结果、事实/标注资源与预算机会，记录实际用量。若本方法多做标注、多次teacher调用，不能隐藏成本后声称严格等资源。

### 11.3 信息干预与输入有效性

- current_only：当前双图/本体/任务/预算；屏蔽所有过去及其旁路。
- true_history：公开前缀，明确实际采样帧数，不称稀疏8图为完整视频推理。
- all/selected facts：同一个E的产物，比较S。
- critical_delete：关键性由独立任务/证据审核定义，不按掉分最大倒选。
- fact_preserving：事实相同释义/顺序，检查稳定性。
- exact_repeat：完全相同条件重复，查数值/安装/服务随机性。
- no_explicit_actions：去显式动作，但图像/本体仍可能含动作信息。
- lawful_swap：来自真实物理可行的匹配前缀；不合条件就不做、不找任意供体凑数。
- shuffle/mismatch：可以作为OOD压力，但不能单独支撑事实因果证明。

不同condition使用独立无状态VLM调用，不共享先前对话/KV/答案记忆。人工current-only判断者不能先看过该case历史/隐藏答案。帧数/mask对齐控制格式，不代表精确等token/等计算；成本实测。

### 11.4 指标、分母与不确定性

| 指标 | 报告方式 |
| --- | --- |
| RSR绝对恢复率 | 原剩余预算内成功数/共同有效case-seed数，同时报组数与case数 |
| 配对历史效果 | 同checkpoint/case/seed的history-current；分别报救回、伤害与持平 |
| 决策质量 | 有效候选选择率、多有效解集合、相对候选结果的regret |
| 证据质量 | 引用有效、事实支持、关键证据召回、幻觉/不确定，人工抽检单列 |
| 代价 | 全部试验步数/预算耗尽、wall latency、图/token、GPU时、调用与存储 |
| 非伤害 | 当前充分场景、正常任务、误触发后成功损失 |
| 覆盖 | 源→候选→确认失败→可重建→可执行→信息诊断，各层分子分母 |

组是统计独立单位；seed、多个锚点、同义句和branch不是独立case。先按根组汇总，使用cluster bootstrap/合适的配对检验；主比较与多重检验规则提前声明。少于10组不报精细CI，10组也不等于功效充分。

主比较按根组等权：先平均组内case/seed，再跨组平均；同时给出micro成功数/分母，避免某个组因生成更多锚点而主导结论。两个口径分别命名，不能表中用micro、显著性却假装每个branch独立。

正式样本量用pilot配对方差和预设最小关注差异（可先设10pp）估算。30个case只为pilot，不保证显著性，不承诺SOTA。

模型/服务超时、JSON/格式错误按非成功进主表并另报错误率；共同现场损坏统一隔离。不要方法各删各的难例，也不要只报成功分支平均耗时。

## 12. 分阶段工作包与门槛

### M0：从零基础闭环

产出：`PREFLIGHT.md`、依赖锁/源码hash/模型manifest、actor/sim/VLM真实smoke、≤8条部署轨迹、至少一个新机现场跨进程验证、契约测试。

不要求旧38项测试原样存在。若导入旧代码，可先跑其38项作回归；若从零开发，重新实现同类契约并记录实际测试数，不伪造“38 passed”。

通过条件：实际模型/传感/动作/成功判定可核对；同现场再现与资源记账成立。未满足不进入批量源采集。

### M1：连续源采集、语义审核、首个家族

默认自然首批：LIBERO-10任务 `[0,1,3,4,5,7,8,9]` × 初始索引 `[4,5,6,7]`，env seed7，共≤32源；先校验初始化存在，不静默换题。旧开发使用过的来源不能当最终test。

默认受控源≤12，分开记账。从两种短指令可执行性起步，再构造真实遮挡前缀。实现候选记录后继续、离线canonical锚点和盲化审核。

产出：完整源流程账目、审核包、TaskAdapter、复现recipe、合法证据位置。32自然源若确认失败少于8个，先报告产率；不要降模型、破坏预处理或缩短预算追求失败。

### M2：候选表与信息门槛

首批最多8个case，每个≤4候选×3 seeds `[0,1,2]`，≤96实际分支。8个case来自几个根组必须如实写；不足以作最终统计。

教师在看到候选执行结果前，分别用current/history作选择并封存。弱Qwen无收益时，使用合法输入的人类/更强教师定位，而不是直接判信息无效。付费或外部上传需研究者另行同意。

预先指定2个case×2输入条件×3seeds，≤12条fresh复核；不按结果挑。输出 `GATE_REPORT.md` 与病例级表。

| Gate | 必须查明什么 | 失败/不确定时的行动 |
| --- | --- | --- |
| G0 工程 | 输入、预算、重建、probe、无reset一致 | 修工程，不训练 |
| G1 语义 | 失败不是正常接触转换，有审核证据 | 修定义/审核；无人审则provisional/BLOCKED |
| G2 信息 | 当前缺什么，历史哪处提供，是否仍有效 | 保留当前充分对照，换合法信息问题，不伪造差距 |
| G3 执行 | 至少两个不同选择可执行，正确选择能影响后果 | 缩小场景/接口；共同适配另起实验 |
| G4 使用 | 固定teacher从事实作合理决定且有实际收益证据 | 查reader/证据/actor，不能默认SFT必然解决 |

可以在开发阶段参考“有效候选约≥60%成功、历史较current约≥10pp”判断是否值得投入，但这不是8case的统计证明，也不是必须凑出的结果。状态用PASS/FAIL/INCONCLUSIVE/BLOCKED，附原始计数与原因。

### M3：数据扩量与共同R训练

通过M2复盘后，先扩至约30独立可审核case的pilot，不用重复seed凑数。训练3步smoke→≤20case过拟合→分组验证，建立B3/B4强对照与事实控制。

reader训练好才冻结版本。若未见组不能用事实作正确选择，先排查输入/标签/学习，不进入utility大采样。正式训练扩至数百组的预算另定，不以pilot过拟合代替方法结果。

### M4：固定消费者的证据收益训练

冻结E/R/A/catalog/预算，构造5类集合的选择与Delta。实现标签依赖审计和可重算；train内按根组交叉拟合检查reader过拟合造成的虚假收益，不使用val/test回报训练S。

训练MLP，与all/random/relevance及同帧raw对照。换R时重生成/校准consumer绑定标签。若总选all-facts且无成本收益，选择器分支可能不成立，不能靠修改主指标掩盖。

### M5：新场景fresh主评测与外部泛化

冻结配置与组级test后，fresh跑全部方法。分别报告natural/controlled、关键事实控制、当前充分非伤害、成本、在线误触发。

外部优先小样本LIBERO-Recover；无匹配完整前缀的case只做末态恢复迁移，或重新采合法前缀，不能编配视频。REBOOT/RACER先做离线证据/监督审计，跨动作生态不作为首轮依赖。

最终增加同actor在线产生失败并触发恢复的端到端测试，观察总成功与误介入。固定题库结果不等于完整部署效果。

### M6：发布与结论

数据卡/许可、分组、原始与派生资产hash、环境/模型/代码版本、完整成功失败账目、future隔离、最小复跑示例、所有基线配置与成本。分别回答RQ1–4，允许负结果。

| 项目 | 首轮M0–M2上限 | 通过复盘后的pilot累计上限 |

### 14.2 默认不授权的扩展

不使用付费API、不自动上传数据、不改驱动/挂载、不杀他人任务、不扫SSH私钥、不自动扩成八卡联合训练。新大模型下载、系统变更、正式大规模评测需要报告瓶颈和成本后由研究者决定。

### 14.3 明确停止条件

- 重建/输入/预算契约失败：停止该批评分，修复或隔离，不放宽阈值救结果。
- 失败语义不明：保留provisional，不宣布已采到目标数据集。
- 正确合法指令无法执行：修actor接口/任务范围，暂不训练历史选择器。
- 合法教师也无信息收益：定位信息不足、current充分、reader不足或统计不足，不自动扩大模型。
- 直接历史SFT已等好：方法新机制可能无价值，转向成本/鲁棒性或保留bench结论。
- 磁盘/显存/时限触顶：安全中止、保存收据，不能换随机模型继续凑结果。

## 15. 最需要防止的质疑与失误

| 质疑 | 应对与证据 | 不允许的应对 |
| --- | --- | --- |
| 自己设计题自己刷分 | natural覆盖、当前充分控制、独立审核、未见组、外部测试 | 按Ours胜负筛test |
| 只是更强训练/更多数据 | 强直接训练基线、同支持帧、标注/更新/计算账目 | 只比未训练小模型 |
| 历史只是改变了动作 | 审核事实→正确选择→真实后果 | 仅展示不同文本/轨迹 |
| 选择器就是普通value memory | 逐项比较标签、消费者绑定与边际收益；强all-facts/relevance对照 | 宣称首次收益驱动记忆 |
| 信息来自真值/未来 | allowlist、出处、isolated test、teacher先封存 | 把oracle答案写进事实/候选 |
| 模型当前已能做，不需要历史 | 不惩罚饱和模型；分层报绝对率、成本与非伤害 | 故意削弱current-only |
| 复制现场是额外免费reset | 每方法一次预算，评测重建与正式rollout分离 | 把多分支最佳结果当部署成绩 |
| source不是自身失败 | 记录source_actor；natural/controlled分开；最终在线自身失败 | 脚本前缀冒充自然失败 |
| selector收益只对一个reader | 说明consumer依赖，换reader/actor做迁移或重新标注 | 宣称普适信息价值 |
| 八卡5090可以解决一切 | 先验信息与控制能力门槛、单卡校准、实际吞吐 | 用硬件升级代替方法论验证 |

可接受的有价值负结果包括：历史只帮助少数遮挡场景；事实够但actor能力主导；普通历史训练足够；选择器只省成本或根本无益。结论范围应跟证据走。

## 17. 报告格式与研究者验收

每阶段 `reports/GATE_REPORT.md` 至少写：

1. 环境：hostname、实际GPU型号/UUID、代码/模型/processor/config版本、根路径。
2. 范围：本次新跑、旧导入、fresh、表复用、重复诊断分别多少。
3. 流程：源→候选→审核→重建→执行的完整计数与排除原因。
4. 结果：共同组数/case数/seed数/分支数；每例成功、步数、错误与指令。
5. gate：PASS/FAIL/INCONCLUSIVE/BLOCKED及依据，不用“基本跑通”遮盖失败。
6. 成本：GPU·小时、下载、磁盘、teacher调用、延迟与预算。
7. 解释：信息无新增、提取错、reader不会用、actor不会做、预算不足或样本不足，哪些已定位，哪些仍未知。
8. 下一步：最小有信息量实验、依赖、预计预算与停止条件。

研究者验收清单：

- [ ] 新机器不依赖旧路径，模型/环境有独立hash与真实smoke。
- [ ] 历史事实、设计与假设明确分开；没有把旧负结果改成正结果。
- [ ] 源执行确实完整、候选不被直接叫失败、人工审核状态诚实。
- [ ] 输入无未来/真值/ID捷径，恢复后缀可拼接且T+1/T正确。
- [ ] 每方法同现场/actor/候选/预算/随机规则，无免费reset。
- [ ] 有合法历史证据与正确指令的真实执行验证。
- [ ] current充分、历史无益/有害与失败分支都保留。
- [ ] 同支持帧直接历史、强SFT、all-facts与简单退回已规划/实施。
