# 任务参考 CFG：方法说明与最小实验计划

日期：2026-11-12。状态：方案与代码路径审查，**尚未实现新 CFG、未启动新 GPU 试验、未修改原模型/推理代码或旧结果**。

## 1. 决策

值得开展一个 training-free 机制实验，但不把它当成已经成立的历史利用方法。分别验证：

1. **指令利用能力**：在同一修正信息下，采样时的条件差分引导是否优于直接条件化？
2. **历史信息价值**：上述机制是否使模型真正利用了当前观测没有的失败证据？

第一个问题成立不等于第二个成立。现有黑碗、白杯题是当前充分控制，不能单独验证第二个问题。

## 2. 正确定义

经典 CFG 使用空条件作参考：

`v_CFG = v_empty + s * (v_cond - v_empty)`。

建议中的方案使用：

- 正分支：`c+ = T + X`，原任务加一条有证据支持、可执行的修正。
- 参考分支：`cT = T`，保留原任务，只去掉新增修正。
- `v_recovery = v_plus + lambda * (v_plus - v_task)`。

`lambda=0` 退化为直接使用 T+X；`lambda=4` 等于 `5*v_plus-4*v_task`。参考分支仍然有任务和当前图像，因此更准确的名字是 **task-relative / contrastive CFG**，不是完全无条件模型。

这里的 v 是同一去噪时刻、同一 noisy action latent 下的网络速度场输出。不是把最终两段动作相减，不是把机械臂位移放大，也不是对两句自然语言做数值运算。引导后的 v 交给原 flow scheduler，完成整个采样后才反归一化、执行动作。

CFG放大的是模型对 X 的响应，不能保证该响应正确。它既可能强化有用操作，也可能强化幻觉、错误对象绑定或微小模型误差。Flow 的线性引导也不自动给出某个指定终端分布或成功率的保证。

## 4. 第一版只干预动作侧

保持官方视频CFG=5、视频/动作20/50个去噪步、权重、动作接口、恢复预算及60步交回规则不变。先不同时改视频和动作两边。

建议统一维护三个文本分支：`T+X`、`T`、空文本。视频仍用第一与第三分支的标准CFG；动作可选择普通条件、空文本标准CFG或任务参考CFG。三分支共用权重，不是加载三套模型。

工程契约：

1. 一次动作采样中的三分支必须读取相同 noisy action、时间步、当前图像、预测视频和已执行动作。
2. 各分支有对应自己的文本条件及KV条目；同一物理历史、分支独立编码，不能复制一个已混入正条件的缓存冒充任务参考缓存。
3. 视频阶段、动作阶段及真实观测回灌阶段都要保持三分支的批次顺序和缓存维度一致。不能只在最后的公式里多减一个张量。
4. 本轮动作参考分支仍共享由正条件引导产生的预测视频；测试的是**给定相同视频规划时的动作侧增量**，不是把 X 从全部世界模型路径中移除。
5. 混合在 action scheduler 之前、反归一化之前进行。原有mask、条件帧、未使用动作维度规则保持不变。
6. 不直接把现有负文本换成T：这会同时改变视频参考分支，混淆动作侧归因。
7. 原 `_reset` 的负条件编码开关取决于视频 guidance_scale，而不是统一的 use_cfg；未来若关闭视频CFG、只开动作CFG，也要检查这一点。首轮固定视频=5避免悄悄触发不同路径。
8. 多分支会改变计算与显存。基线使用相同扩展代码路径；记录实际分支数、模型评估次数、延迟和峰值显存，不笼统声称“免费”或“一定翻倍”。

伪代码（不是可直接替换有状态WAM的完整实现）：

```python
v_plus = model_velocity(a_t, t, obs, shared_predicted_video, T_plus_X, cache_plus)
v_task = model_velocity(a_t, t, obs, shared_predicted_video, T, cache_task)
v_guided = v_plus + lam * (v_plus - v_task)
a_next = action_scheduler.step(v_guided, t, a_t)
```

## 5. 阶段0：数值与缓存门槛

先用固定当前观测和噪声做单chunk检查，不做大规模rollout：

- lambda=0 与同一扩展代码路径的直接T+X相同。
- X为空，T+X与T相同，引导差值应为0（数值容差预声明）。
- 同一文本分别编码到两个分支，差值应接近0；重复请求/重建缓存后结果可复核。
- 分支只变文本时，输入图像、动作噪声、时间步、归一化、预测视频及历史身份哈希一致。
- 至少验证第一chunk、真实观测回灌后的下一chunk、60步交回后的chunk；首chunk正确不代表时序缓存正确。
- 保存相对差分范数 `||v_plus-v_task||/(||v_plus||+eps)`、guided输出范数、非有限值、动作饱和情况。差分非零不是“理解了修正”的证据。

若不通过，先修实现；不以任务成功率掩盖代码错误。

## 6. 阶段1：检验“指令放大”

复用已归档的两个场景，只作为开发与接口诊断。各方法相同起点、剩余预算（黑碗483、白杯521）、完整前缀、候选修正和actor。

固定合法教师短修正X，不在每个lambda下重新调用VLM改写，以免混入教师采样差异。首先用同一冻结模板拼接T+X，不使用额外模型或训练。

| 编号 | 正条件 | 动作侧采样 | 要排除的解释 |
| --- | --- | --- | --- |
| B0 | T | 直接条件，动作CFG=1 | 原策略本身能继续 |
| B1 | 单独修正P | 直接条件，动作CFG=1 | 复查旧的替换式prompt |
| B2 | T+X | 直接条件，动作CFG=1 | 只是保留完整任务就变好 |
| B3 | T+X | 以空文本为参考的标准动作CFG | 只是普遍增强语言条件 |
| B4 | T+X | 以T为参考的纠正CFG | 是否确有新增修正方向的价值 |

B3使用 `s=1+lambda`，B4使用lambda。开发网格lambda为 `{0.5,1,2,4}`，lambda=0共享B2，不重复记为不同方法。不要上来只测5倍条件输出。

总计11个配置（B0/B1/B2，以及B3、B4各4个强度）×2场景×3种子 `{7,17,27}` = **66条闭环分支**。先完成一个种子的22条；若数值爆炸或普遍损害，暂停扩种子并给出诊断。原生旧实现另做回归，主比较都用一致的扩展采样路径，避免batch变化导致的数值差异混入算法对比。

不在恢复期间系统reset；所有恢复动作计入原剩余预算。60步后各分支重建为统一原任务，额外纠正lambda归0。

## 7. 阶段2：历史是否真的提供信息

仅当阶段1数值正确且有可执行收益时进入。使用新的、按根场景分组的development/留出组，预先审核失败语义及信息结构，不按B4是否获胜筛test：

- 历史有额外信息：物体先可见、随后进入某个遮挡区域；当前双视角/本体/任务不能直接泄漏位置，历史能指向不同的可执行搜索操作。
- 当前充分控制：保留本轮失抓题及类似任务，不惩罚不需历史就成功的模型。
- 合法但无用的信息控制：使用真实、与当前决定无关的事实，检查是否只是任何附加文本都受益。

允许无历史模型在预算内主动搜索。先验证对应动作菜单能由WAM完成，再收集更多复杂历史。固定同一VLM、模板、actor和验证阶段选定的lambda；分别用当前信息生成X_C、完整失败前缀生成X_H，再比较直接条件与任务参考CFG。

如果X_C和X_H完全相同，不能期待确定性采样产生历史独有收益。若有历史只改变了文风/措辞，需加入事实保持改写等控制；不能把prompt敏感性当作历史因果价值。

## 8. 指标与决策

主指标：原任务成功率。辅助指标：重抓是否成功、目标摆放/抽屉谓词是否完成、失败与成功全部分支的控制步、接触异常、动作饱和、非有限值、推理时间、显存及模型评估次数。

配对报告每个场景/种子上的救回、损害、持平。两场景只能做机制pilot，不能得出泛化或显著性结论。lambda在development选定后冻结，不能按test case各选最优值；best-of-grid单列为带全部试验成本的事后诊断。

- B2≈B4：无需新增差分引导；可能直接条件已足够。
- B3≈B4且都优于B2：更可能是一般条件增强，未证明任务参考的独特作用。
- B4优于B2/B3，但X_C与X_H收益相同：支持纠正执行机制，不支持历史必需贡献。
- B4在留出的历史敏感组中更会利用X_H，且事实删除/保持改写符合预期：才支持继续发展历史证据驱动恢复方法。
- 指令本身错误或动作接口无法执行：CFG可能放大错误，不能代替证据审核或必要的共享能力适配。

## 9. 相关工作边界

- [Classifier-Free Diffusion Guidance](https://arxiv.org/abs/2207.12598)：条件/无条件预测组合的基本方法。
- [Composable Diffusion Models](https://arxiv.org/abs/2206.01714)：生成更新空间中组合条件与否定已有经典先例。
- [REACH（CVPR2026）](https://openaccess.thecvf.com/content/CVPR2026/html/Ke_REACH_Explicit_Recovery_Behavior_for_Diffusion_Policies_CVPR_2026_paper.html)：使用错误执行历史构造负动作提示、避开不良动作模式；不能宣称首次以失败经验引导扩散恢复。本文检查了官方摘要与补充材料，正文PDF获取失败，不把未核实实现细节当成已完成复现。
- [CFG-Policy](https://arxiv.org/abs/2610.14936)：已有在采样时组合策略score/velocity的机器人方法；其RL分支设计不同于本方案的同一冻结模型、不同文本条件。
- [Completion Aware Guidance](https://arxiv.org/abs/2610.01559)：WAM中通过token级交叉注意力K/V缩放促进阶段完成，不是本文的两条件速度差分。
- [Self-correction Optimization](https://arxiv.org/abs/2610.10400)：在多模态生成中利用全条件/反事实条件差分与状态保持约束，进一步限制“新增事件差分”本身的新颖性；其视频生成结果不能等同机器人闭环恢复。

所以本轮定位是**可行性与归因实验**。单独“把CFG加到recovery”不应作为论文创新主张。
